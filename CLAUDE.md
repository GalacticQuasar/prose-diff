## Commands

```sh
npm run dev                          # Vite dev server
npm test                             # Vitest, single run
npx vitest run -t "flags only"       # run tests whose name matches
npm run build                        # type-check, vite build into dist/, compile the CLI into dist-cli/
npm run preview                      # serve dist/
cli/prose-diff.ts <file>             # file mode from source (needs dist/ built)
npm pack --dry-run                   # list what `npm publish` would ship
```

No linter is configured. `npm run build` is the type check (`strict`, `noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`, so type-only imports need `import type` / `type X`). It checks `src/` with `tsconfig.json` and `cli/` with `tsconfig.cli.json`. In the repo the CLI runs as TypeScript directly through Node's type stripping, so `cli/` imports use `.ts` extensions and only erasable syntax (no enums or parameter properties). Node won't strip types inside `node_modules`, so the published package's `bin` is the compiled `dist-cli/prose-diff.js` (`tsconfig.cli.build.json`, which rewrites the `.ts` imports and skips tests). The package ships no runtime dependencies: Vite bundles `diff` and the font into `dist/`, and the CLI uses Node built-ins only, so everything is a devDependency. It supports Node 20+ (`engines`), so the CLI must not use newer Node APIs.

## What it is

Prose Diff is a browser app with no framework, plus a CLI, published to npm as [`prose-diff`](https://www.npmjs.com/package/prose-diff). In the web app (hosted at https://prose-diff.vercel.app, a static build of `dist/`) you paste an original and a revised text, review word-level changes inline, accept or reject each one, and copy the merged result. In file mode, `prose-diff <file>` snapshots a file and serves the same app locally; you review the file's edits since the snapshot and apply the merged result back to the file. The user-facing behavior and keyboard shortcuts are documented in README.md. Keep the README's "How it works" and "Keyboard shortcuts" sections, and the in-app help dialog in `index.html`, in sync when behavior changes. ## Architecture

The data flow goes in one direction: `diff.ts` (pure) → `state.ts` (store) → `render.ts` (DOM), with `main.ts`/`keyboard.ts` wiring events to state actions (directly, or through `actions.ts` when an action also needs UI feedback).

- **`diff.ts`**: pure and tested (`diff.test.ts`, including a seeded random-text merge check), with no DOM access. `buildSegments` runs jsdiff's `diffLines`, then `diffWordsWithSpace` only inside each removed+added block of lines (much faster than one word diff over the whole text, and it keeps insertions from being split: a whole-text word diff can match a few tokens of an unchanged line, e.g. `\end{`, against copies inside the inserted text). A block needing more than `MAX_WORD_EDITS` word edits falls back to one whole-block replacement. A count, not a timeout, so segmentation is deterministic. Then `alignToLines` slides pure insertions or deletions that span lines so they cover whole lines. Changes separated only by 1–3 spaces or tabs (`JOINABLE_GAP`) are folded into one change. Change ids are assigned sequentially after grouping, so **ids are positional**: they only stay meaningful for a fixed `(original, revised)` pair and diff algorithm. `changesKey` fingerprints the changes; `state.ts` saves it with the decisions (`decisionsKey`) and drops decisions that don't match when it rebuilds the diff (on load in review, in `compare()` and in `openSession()`). `mergeResult` treats undecided (`pending`) changes as keeping the original text.
- **`state.ts`**: a module-level `state` object plus derived `segments`/`ids`, which are rebuilt (via `rebuild()`) only on load in review, in `compare()`, in `openSession()` and in the undo closure of `continueFromResult()`, not on every update. `update()` replaces state, persists it, and notifies subscribers (`render`). In paste mode it persists the whole state to `localStorage` under `prose-diff:v1`, minus the file-mode fields (`file`, `fileError`, `fileStale`); file mode persists differently (see `fileMode.ts`). `setInputs` intentionally skips notifying (typing shouldn't re-render) and sets `dirty`. `compare()` clears decisions when `dirty` (edited inputs invalidate positional ids) or when `decisionsKey` doesn't match the rebuilt diff's `changesKey`; loading in review applies the same key check. Persisted state is merged over `initial` on load, so new `State` fields need a default there.
- **`render.ts`**: full re-render on every state change (`doc.replaceChildren(...)`). Changes are rendered as `span.chg[data-id]` with a `pending`/`accepted`/`rejected` class. Margin marks, the floating accept/reject buttons (`#change-actions`) and the keyboard-shortcut panel are positioned from measured layout (`getClientRects`), so layout-affecting changes (measure/width, theme, fonts) need a relayout. `relayout()` redoes all of the measured positioning; `render()` ends by calling it. While the minimap shows, `html.minimap-on` hides the native scrollbar (the strip replaces it), which changes the view width, so `render()` sets it before measuring. Whitespace-only edits get display-only `·`/`→`/`¶` markers via `visible()`, and a CR shows as `^M` (Courier Prime has no `␍` glyph); the copied or applied text never includes them.
- **`minimap.ts`**: the `#minimap` overview strip, fixed at the window's right edge, which maps the whole scroll range and works like a scrollbar (click or drag). Like a scrollbar, it takes its width (`--minimap-width`) from the page: `html.minimap-on` pads the body by that much, so the header and toolbar never sit under it. Its ticks are rebuilt on render/relayout; only its viewport box moves on scroll.
- **`measure.ts`**: the page's line length (`--measure`, in characters): the `[`/`]` shortcut and the draggable, keyboard-operable `#page-resizer`. While dragging it previews the width without writing state, then commits on release.
- **`actions.ts`**: actions that pair a state change with feedback: `compareInputs` (toasts instead of comparing two empty inputs), `copyResult` (with a fallback when the Clipboard API is unavailable; reports failure), `nextRound` (with a toast Undo). File mode: `loadFile`/`reloadFile`, `applyToFile` (confirms before reverting undecided changes; a 409 sets `fileStale`) and `watchFile`.
- **`toast.ts`** / **`dom.ts`**: `showToast` (an action button is disabled once the toast hides), and the `$`/`el` DOM helpers.
- **`keyboard.ts`**: one keydown handler with a key→action map. It is ignored while the help dialog is open or while typing. On the paste view, only Ctrl/Cmd+Enter and `?` are active. After every handled key it calls `scrollFocusedIntoView()` (in `render.ts`): it leaves the view alone if the focused change is already comfortably visible, otherwise centers it below the sticky toolbar, or puts its start near the top if it's taller than the view.
- **`index.html`**: holds all static markup (both views, toolbar, help dialog). Scripts look elements up by id at module load.
- **`cli/server.ts`** / **`cli/prose-diff.ts`**: file mode's server, Node built-ins only, no diffing. It snapshots the file at startup (in memory) and serves `dist/`, `GET /api/session` (`{ path, name, original, revised, revisedHash, originalHash }`, reading the file fresh each time), `GET /api/status` (just the two hashes, for polling) and `POST /api/apply` (`{ merged, revisedHash }`; 409 if the file's hash changed, otherwise writes atomically and makes `merged` the new original). It binds to 127.0.0.1, checks `Host`, and requires the URL's `?t=` token in an `X-Prose-Diff-Token` header. The file's text goes through untouched, line endings included (the diff and merge handle CRLF, mixed and lone-CR endings exactly; `visible()` shows a CR as `^M`). Files that aren't valid UTF-8 are refused (415, and at startup) rather than decoded lossily, and apply refuses merged text that isn't well-formed Unicode. Tested in `cli/server.test.ts`.
- **`fileMode.ts`**: `isFileMode` (a `?t=` token in the URL) and the API calls. In file mode, `state.ts` starts in review with no texts, keeps decisions in `sessionStorage` (`prose-diff:file`) and only theme/measure in the shared `localStorage` entry, so the pasted texts are never touched. `openSession` loads a session using the same `decisionsKey` check as `compare()`. `html.file-mode` toggles the `[data-mode="paste"|"file"]` controls (Edit inputs/Continue vs Apply, `n` vs `w`). `watchFile` (in `actions.ts`) polls `/api/status` every 2s while the page is visible, and on focus. When a hash changes, it reloads the session if nothing is decided, and otherwise sets `fileStale`, which shows the toolbar's Reload notice.
- **`style.css`**: a "typed manuscript" look (Courier Prime) with light/dark themes. Theme is `null` (follow system) or an explicit override.

## Releasing

Releases go to npm from `main`. Bump the version with `npm version patch` (or `minor`/`major`), which commits and creates an annotated `vX.Y.Z` tag. Then run `git push --follow-tags` and `npm publish`. The user runs `npm publish` themselves. `prepublishOnly` runs the tests and a full build. A published version can never be reused.
